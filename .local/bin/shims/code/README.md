# Visual Studio Code 命令行命令的装饰程序

程序 `code.py` 是 Visual Studio Code 远程服务器命令行命令装饰器．

## 问题背景

装饰器的初衷始于一个问题，在终端复用器 tmux 中，执行 Visual Studio Code 远程服务器命令行命令时，原命令 `code` 有时将报告错误，表示无法连接到 Visual Studio Code 服务器．

一个可能的原因是，终端复用器服务器进程的寿命往往远远长于创建它的 Visual Studio Code 集成终端．在一个新窗口的集成终端中，用户连接到一个早先创建的终端复用器会话．此时，先前创建该会话的集成终端可能已经关闭，会话中终端的环境变量却仍然指向彼时 Visual Studio Code 服务器为早先的集成终端创建的套接字．早先的集成终端关闭后，该套接字已不再处于监听状态，原命令 `code` 因而无法连接．

## 解决方案

装饰程序的解决思路是，在 Visual Studio Code 服务器仍在监听的套接字中，寻找当前环境变量指向的套接字，或是最近创建的套接字．

装饰器将列出所有处于监听状态的本地套接字与相应的服务进程，执行如下命令，

```bash
ss --listening --no-header --processes --unix
```

为了确认这些套接字属于 Visual Studio Code，程序将筛选出文件名前缀为 `vscode-ipc` 的套接字．接着读取监听这些套接字的进程，由进程可执行文件的路径获取 Visual Studio Code 服务器程序所在的目录，寻找到该目录下的原命令 `code`．

如果当前会话终端的环境变量仍然指向一个处于监听状态的套接字，就沿用之．否则，按照修改时间排序，选用列表中修改时间最新的套接字，即，最近创建的套接字．执行查找到的原命令 `code`，并连接至最后确定的套接字．

## 未来计划

现有方案下，创建会话的集成终端仍未关闭时，装饰程序会沿用该终端的套接字，即使此时，用户可能已经切换至另一个集成终端．

我们的问题局限于终端复用器的使用场景，因此，另一种或许更准确的方法是，直接访问终端复用器的客户端进程，查询客户端进程所在的终端环境中，环境变量指向的套接字．客户端进程所在的终端，正是用户连接到持久会话之前，正在使用的 Visual Studio Code 集成终端．由于该方案需要仔细考虑终端复用器多客户端连接到同一会话的情况，研究其特性，因此，暂时留作未来计划．
